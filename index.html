System Architecture & MVP Report

SPOT1 設計ドキュメント・開発ステップ報告（STEP 1〜7）

STEP 1 技術スタック選定とアーキテクチャ構成

新規フルスタックプロトタイプとして、ビルド不要で即時動作・状態検証が可能な単一ページアプリケーション構成（Vanilla JS + Tailwind CSS + LocalStorage永続化ストア）を採用。本番移行時は Next.js (App Router) + Supabase (PostgreSQL / Realtime / Storage) + Stripe Connect へそのままマッピング可能な正規化データ構造で設計しています。

STEP 2 画面構成とデータベース設計（将来拡張対応）

1. jobs（案件テーブル）

id, client_id, title, description, category, skills[], reward_jpy, duration_hours (1|2|3), deadline, deliverable_spec, attachment_name, is_priority, status (`open` | `matched` | `submitted` | `completed`), assigned_worker_id, created_at

2. applications（応募・排他制御）

id, job_id, worker_id, message, status (`pending` | `accepted` | `rejected`), created_at。受注確定時にトランザクションで他応募を自動クローズし重複受注を防止。

3. messages（リアルタイム連絡）

id, job_id, sender_role, sender_name, body, attachment_name, type (`text` | `system` | `revision` | `delivery`), created_at

4. 自動マッチング拡張フィールド

usersテーブルに `verified_skills[]`, `rating_avg`, `completed_count`, `available_now` を保持し、将来的に即時自動アサインAPIへ拡張可能。

STEP 3〜6 実装済みMVP機能と収益モデル計算ロジック

  • 完全な双方向トランザクション: 右上の「ワーカー視点 / 依頼者視点」を切り替えることで、案件投稿 → 応募 → 承認（募集終了・重複防止） → チャット連携 → 成果物提出 → 検収承認（または修正依頼）の全フローが動作します。
  • 手数料・プラン試算: 通常手数料15% / 法人月額プラン（Pro）手数料10% + 優先表示オプションのリアルタイム計算を依頼作成時および報酬履歴に組み込み済み（実決済APIは未実装と明示）。

STEP 7 動作確認チェックリスト（E2E検証済み）

✓ テスト1（案件作成）: 依頼者視点で新規1〜3時間案件を投稿し、即座にトップ・検索一覧へ反映されることを確認。
✓ テスト2（即時マッチング排他制御）: 複数応募がある状態で1名を「この人に決定」すると、ステータスが進行中になり他候補の重複受注がロックされることを確認。
✓ テスト3（チャット＆成果物検収）: 進行中ワークスペースからメッセージ・ファイル送信、成果物提出、依頼者側の「修正依頼」および「完了承認」による報酬確定を確認。
